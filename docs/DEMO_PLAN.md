# 智行 CampusMind 演示数据与演示流程

## 1. 演示目标

演示应证明第一版系统已经跑通手机端 MVP 主流程：

```text
登录 -> 查看建筑 -> 发布留言 -> 添加课程 -> 生成出发建议
```

## 2. 演示账号

建议准备一个普通学生账号：

| 字段 | 示例 |
|---|---|
| 学号 | 20240001 |
| 用户名 | demo |
| 昵称 | 演示同学 |
| 角色 | student |

密码只用于本地演示，不应写入公开文档或仓库中的明文配置。

## 4. 课程演示数据

建议准备 3 到 5 节课程，覆盖当天和非当天：

| 课程 | 星期 | 时间 | 建筑 | 教室 |
|---|---|---|---|---|
| 数据库原理 | 当前演示日 | 当前时间之后 | 三号教学楼 | 302 |
| 软件工程 | 当前演示日 | 更晚时间 | 一号教学楼 | 204 |
| Python 程序设计 | 其他日期 | 08:00-09:40 | 实验楼 | 机房 A |

演示时应确保至少有一节课位于当前时间之后，便于展示下一节课识别。

## 5. 留言演示数据

每个重点建筑预置 2 到 3 条留言。例如：

| 建筑 | 留言 |
|---|---|
| 图书馆 | 三楼靠窗还有空位 |
| 图书馆 | 今天二楼比较安静 |
| 一食堂 | 中午窗口排队较长 |
| 三号教学楼 | 302 教室投影正常 |

留言内容应健康、简短、贴近校园场景。

## 6. 当前位置预设

建议准备以下手动位置：

| 位置 | 用途 |
|---|---|
| 学生宿舍区 | 展示从宿舍去上课 |
| 图书馆 | 展示从图书馆去教学楼 |
| 一食堂 | 展示从食堂去下一节课 |
| 体育馆 | 展示较远距离估算 |

## 7. 演示流程

1. 打开手机端 H5。
2. 使用演示账号登录。
3. 进入首页，展示建筑点位或建筑列表。
4. 点击图书馆，查看建筑详情。
5. 进入图书馆留言区，查看并发布一条留言。
6. 进入课程表，展示已存在课程。
7. 新增或编辑一节课程。
8. 进入出发建议页。
9. 选择当前位置为学生宿舍区或图书馆。
10. 展示下一节课、预计距离、步行时间、缓冲时间和建议出发时间。

## 8. 演示验收点

| 验收点 | 通过标准 |
|---|---|
| 登录 | 能成功进入首页 |
| 建筑 | 能查看建筑列表和详情 |
| 留言 | 能读取和发布留言 |
| 课程 | 能新增、编辑、删除课程 |
| 建议 | 能识别下一节课并生成出发建议 |
| 兜底 | 定位失败时能手动选择当前位置 |
