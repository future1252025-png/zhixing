# 上课时间、首页与后台提醒（2026-10-09）

## 上课时间

“我的 → 学期设置 → 上课时间”和导入页可添加、修改、删除日期生效的作息调整。例如从 2027-05-01 起，将原 14:00–15:40 改为 14:30–16:10；“下午整体推迟 30 分钟”同时调整所列下午时段，避免只改第一门而与后续课冲突。结束日期可留空；这是明确日期，不是未经确认的每年自动切换。

规则只作用于起止时间均匹配的常规课程，不改导入原始记录，不影响生效前的课表。单独补课保留明确指定的时间。同一原时段的规则日期不能重叠；后端按每个实际日期检查与其他课程、补课的冲突，并在冲突时回滚。

课表、首页和课程提醒共用日期实例化函数。生效日在周中时，课表可同时显示新旧时段。学期缓存保存规则，规则单独改变也会刷新；旧客户端只保存开学日期和周数时不会清空已有规则。

后端需先运行迁移 `20261009_13`（`alembic upgrade head`），再启用新版客户端。迁移新增 `semester_settings.time_rules`，默认空列表，不批量修改课程或补课数据。

## 首页

首页只显示尚未开始的下一门课，开课当分钟立即切换，不等待下课。分钟边界和恢复前台时更新，不依赖重新请求服务器。课表中的当前上课高亮仍按起止区间显示。旧出行 API 保持当前课程语义，但也应用日期作息和补课规则；它不驱动新版首页。

## Android 提醒

两处代码缺口：旧实现只在 WebView 打开时安排当天课程；另外，插件 `getPending()` 读取保存记录，不等于系统 AlarmManager 仍持有闹钟，旧代码会把相同签名的记录误当成无需恢复。

现在列表仍只显示今天，Android 会提前安排未来 30 天的课程以及自定义事项（合计最多 400 条，优先最近的提醒）。通知交给系统，由现有原生广播接收器执行，进程退出后不靠 JavaScript 定时器触发。App 冷启动、恢复前台会使用相同 ID 重新登记未来通知；断网时保留同一账号已登记的未来课程并尝试恢复，不删除为下一天安排的通知。

已有通知和精确闹钟授权、勿扰以及厂商后台策略仍然有效；没有添加常驻前台服务或强制修改系统权限。“我的 → 通知设置”提供后台限制检查、应用/省电设置入口和 1 分钟后后台测试。系统设置返回不等待 Activity 回调，避免厂商设置页面不回调导致一直加载。

系统“强行停止”与划掉最近任务不同：强行停止会使应用处于 stopped 状态，不能承诺仍提醒，重新打开后重排。未授予“闹钟和提醒”时会降级为非精确通知，系统可能延迟。厂商可能把清理后台视作更强的限制，仍需真机验证并按需允许后台运行/自启动。网页关闭后仍不能保证提醒。

用户超过 30 天未打开 App、到达 400 条上限，或在其他设备修改课表后，都需要重新打开本机更新。本机已登记的通知不要求平板或手机当时联网，但离线期间无法获知其他设备的新修改。

依据：[Android 闹钟](https://developer.android.com/develop/background-work/services/alarms)、[Android stopped 状态](https://developer.android.com/about/versions/15/behavior-changes-all#stopped-state)、[Capacitor 本地通知](https://capacitorjs.com/docs/apis/local-notifications)。

## 导入入口

原生 App 只显示教务网站采集入口，保留采集后的时间核对和确认，不再显示文件选择器。网页版（包括手机浏览器访问的网页）仍支持 HTM / HTML / XLS / XLSX。以运行平台区分，不以屏幕宽度误判。
