# 03_需求分析说明书：需求分析说明书

## 1. 功能需求

## 1.1 用户认证

### 需求编号：FR-001

用户可以通过学号、用户名和密码注册。

### 需求编号：FR-002

用户可以通过学号或用户名登录系统。

### 需求编号：FR-003

系统使用 JWT 维护登录状态。

### 需求编号：FR-004

用户分为普通学生和管理员两种角色。

---

## 1.2 校园地图

### 需求编号：FR-005

系统首页展示湖北大学卡通化校园地图。

### 需求编号：FR-006

地图上展示主要建筑点位。

### 需求编号：FR-007

用户点击建筑点后，进入建筑详情页。

### 需求编号：FR-008

用户可以查看建筑名称、类型、简介、位置等信息。

---

## 1.3 建筑聊天室

### 需求编号：FR-009

每个建筑拥有一个默认聊天室。

### 需求编号：FR-010

每个建筑可以包含多个室内频道，例如 101 教室、自习区、食堂一楼等。

### 需求编号：FR-011

用户可以查看某建筑的聊天消息。

### 需求编号：FR-012

用户在建筑允许范围内时，可以匿名发送消息。

### 需求编号：FR-013

用户不在建筑允许范围内时，只能查看消息，不能发送消息。

### 需求编号：FR-014

聊天室消息前台显示为“匿名同学”。

### 需求编号：FR-015

后台数据库必须保存真实 user_id，用于违规追溯。

---

## 1.4 定位判断

### 需求编号：FR-016

系统通过浏览器 Geolocation API 获取用户当前位置。

### 需求编号：FR-017

系统根据用户坐标和建筑坐标计算距离。

### 需求编号：FR-018

如果距离小于等于建筑 radius，则允许发言。

### 需求编号：FR-019

如果定位失败，用户只能查看消息，不能发言。

---

## 1.5 课程表

### 需求编号：FR-020

用户可以添加课程。

### 需求编号：FR-021

用户可以修改课程。

### 需求编号：FR-022

用户可以删除课程。

### 需求编号：FR-023

用户可以查看个人课程表。

### 需求编号：FR-024

课程需要包含课程名、星期、开始时间、结束时间、教学建筑、教室、教师等信息。

---

## 1.6 日程规划

### 需求编号：FR-025

系统可以识别用户当天下一节课。

### 需求编号：FR-026

系统可以计算当前位置到下一节课建筑的大致距离。

### 需求编号：FR-027

系统可以根据距离、步行速度、缓冲时间计算建议出发时间。

### 需求编号：FR-028

系统可以在建议出发时间前提醒用户。

### 需求编号：FR-029

用户可以输入临时事项，系统基于时间和地点给出简单规划建议。

---

## 1.7 管理后台

### 需求编号：FR-030

管理员可以新增、修改、删除建筑信息。

### 需求编号：FR-031

管理员可以查看聊天消息。

### 需求编号：FR-032

管理员可以隐藏或删除违规消息。

### 需求编号：FR-033

用户可以举报消息。

### 需求编号：FR-034

管理员可以处理举报。

---

# 2. 非功能需求

## 2.1 易用性

界面简洁，适合学生在手机浏览器中使用。

## 2.2 性能

第一版支持小范围测试，目标同时在线 50 人以内。

## 2.3 安全性

- 密码必须加密保存。
- 前台匿名，后台可追溯。
- 管理员接口需要鉴权。
- 聊天消息需要基础敏感词过滤。

## 2.4 可扩展性

系统应预留：

- 校园统一身份认证接口。
- MySQL 数据库迁移空间。
- 高德地图或腾讯地图 API 接入空间。
- 更复杂 AI 推荐接口。

## 2.5 兼容性

优先适配：

- Chrome 浏览器。
- Edge 浏览器。
- Android 手机浏览器。
- 微信内置浏览器。

## 2.6 可部署性

系统应支持本地运行和云服务器部署。
