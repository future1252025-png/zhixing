# 智行 CampusMind MVP 功能边界

## 1. MVP 原则

第一版 MVP 的最高优先级是：

```text
能运行、能演示、能写进课程设计文档。
```

所有功能都围绕手机端主流程服务。凡是会明显增加后端复杂度、联调成本或外部依赖风险的功能，第一版都后置。

## 2. P0 必做功能

| 模块 | 功能 | 说明 |
|---|---|---|
| 用户认证 | 注册、登录、退出 | 使用简化账号体系和 JWT |
| 首页入口 | 建筑点位或建筑列表 | 第一版可使用静态校园地图或列表式入口 |
| 建筑信息 | 建筑列表、建筑详情 | 展示名称、类型、简介、位置等 |
| 建筑留言 | HTTP 留言区 | 获取留言列表、发布留言，不做实时聊天 |
| 课程表 | 课程增删改查 | 维护课程名、时间、建筑、教室、教师 |
| 日程建议 | 下一节课识别 | 根据当前星期和时间查找下一节课 |
| 出发建议 | 步行时间和建议出发时间 | 使用规则算法估算 |
| 定位输入 | 浏览器定位 + 手动选择当前位置 | 保证演示环境可用 |
| 演示数据 | 建筑、用户、课程、留言 | 支撑完整演示流程 |

## 3. P1 有余力再做

| 功能 | 价值 | 后置原因 |
|---|---|---|
| PWA 桌面图标 | 提升手机端体验 | 对主流程不是必要 |
| 简单敏感词过滤 | 展示内容治理意识 | 可作为后续增强 |
| 建筑搜索 | 提升查找效率 | 建筑数量少时不强依赖 |
| 个人中心 | 管理用户信息 | 第一版可只做退出登录和位置兜底 |
| 课程提醒提示 | 增强日程价值 | 浏览器通知权限和兼容性有风险 |

## 4. P2 第一版不做

| 功能 | 不做原因 |
|---|---|
| WebSocket 实时聊天 | 增加联调、连接状态和异常处理复杂度 |
| 多频道聊天室 | 放大数据模型和页面复杂度 |
| 完整管理员后台 | 对主演示流程帮助不大 |
| 举报审核工作流 | 依赖后台和内容治理流程 |
| 真实地图 SDK | 申请、接入、样式和坐标适配成本高 |
| 真实 AI 大模型 API | 账号、费用、稳定性和调试风险高 |
| 室内定位 | 技术难度高，不适合个人 4 周 MVP |
| 学校统一身份认证 | 接入不可控，课程项目不应强依赖 |
| 推送通知 | 浏览器权限、HTTPS 和兼容性复杂 |

## 5. 验收闭环

MVP 完成后，演示者应能完成：

1. 注册并登录。
2. 在手机端首页查看建筑入口。
3. 进入建筑详情。
4. 查看和发布建筑留言。
5. 添加一节课程。
6. 查看课程表。
7. 获取下一节课。
8. 使用定位或手动当前位置生成出发建议。
