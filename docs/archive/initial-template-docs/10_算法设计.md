# 10_算法设计：算法设计

## 1. 位置判断算法

## 1.1 输入

```text
用户纬度 user_lat
用户经度 user_lng
建筑纬度 building_lat
建筑经度 building_lng
建筑允许半径 radius
```

## 1.2 输出

```text
allowed: true/false
distance_meters: 用户到建筑中心点距离
radius: 建筑允许半径
```

## 1.3 计算方式

使用 Haversine 公式计算两点之间距离。

## 1.4 判断规则

```text
如果 distance_meters <= radius：
    allowed = true
否则：
    allowed = false
```

## 1.5 失败处理

如果用户拒绝定位或定位失败：

```text
allowed = false
message = "无法获取当前位置，仅可查看消息"
```

## 2. 日程规划算法

## 2.1 输入

```text
当前时间 current_time
当前星期 weekday
用户当前位置 user_lat, user_lng
用户课程表 courses
建筑表 buildings
```

## 2.2 输出

```text
下一节课
目标建筑
距离
预计步行时间
缓冲时间
建议出发时间
文字建议
```

## 2.3 查找下一节课

规则：

1. 只查询当天课程。
2. 找开始时间晚于当前时间的课程。
3. 按开始时间升序排序。
4. 取第一条作为下一节课。

如果当天没有下一节课：

```text
返回：今天暂无后续课程
```

## 2.4 步行时间计算

假设学生平均步行速度：

```text
80 米/分钟
```

计算：

```text
walk_minutes = ceil(distance_meters / 80)
```

## 2.5 缓冲时间

默认缓冲时间：

```text
5 分钟
```

## 2.6 聊天关键词影响

读取目标建筑最近 30 分钟消息。

如果出现以下关键词，增加缓冲时间：

```text
施工
绕路
堵
人多
排队
拥挤
关门
封路
```

规则：

```text
出现 1-2 次：缓冲时间 +3 分钟
出现 3 次及以上：缓冲时间 +5 分钟
```

## 2.7 建议出发时间

```text
suggest_departure_time = course_start_time - walk_minutes - buffer_minutes
```

## 2.8 迟到判断

如果当前时间已经晚于建议出发时间：

```text
提示：建议立即出发，可能存在迟到风险
```

## 3. 临时事项规划算法

第一版可以做简单规则。

## 3.1 输入

```text
用户输入事项 text
事项地点 building_id
事项预计耗时 duration_minutes
目标时间 target_time，可选
```

## 3.2 输出

```text
建议开始时间
建议结束时间
是否与课程冲突
```

## 3.3 冲突判断

如果事项时间与课程时间重叠：

```text
提示：该事项与课程冲突，建议调整时间
```

## 4. 敏感词过滤算法

第一版使用关键词列表。

处理流程：

```text
用户发送消息
→ 后端检查是否包含敏感词
→ 如果包含，拒绝发送或替换为 ***
→ 如果不包含，保存并广播
```

## 5. 防刷屏规则

第一版规则：

```text
同一用户 10 秒内最多发送 3 条消息
超过限制则返回：发送过于频繁，请稍后再试
```
