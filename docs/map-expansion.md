# 地点与建筑扩充准备

## 当前基线（2026-09-20，本地种子，不是生产库快照）

- 102 个地点，30 个地点已有原生高德 POI 关联；种子中还有同名停车场，不能按数组顺序重新导入或重编号。
- 现有 `buildings.id` 是课表、聊天和地点关联的稳定身份。建筑与食堂、广场、驿站等地点共用这套身份；扩大内容不等于在底图再画一套标点。
- 原生地点继续靠明确的 POI ID 关联进入频道；同一建筑可关联多个 POI，一个 POI 不能属于两个建筑。距离近或名称相似只作候选，不自动合并。
- 前端目录改为每次展示 40 个，可加载更多；搜索覆盖完整目录，不再截断在第 120 个地点。此方案适用于当前数百级目录，达到数千条时再做后端分页和搜索，不宣称无限扩展。

## 建议先分批补全

先按现有武昌校区准备，新增范围最终由用户确认：教学/实验楼 → 图书自习 → 宿舍食堂 → 体育活动 → 医疗快递与其他生活服务。暂不录入未经确认的地点，也不主动扩大到其他校区。

每条采集记录核对：完整名称、校区/区域、地点类型、常用简称、真实经纬度及坐标系、来源与核验时间、是否已有对应建筑 ID、原生 POI ID（可选）。同名地点须通过区域/楼栋区分，不使用会随排序变化的“（1）（2）”作为新地点身份。

数据库继续保存 WGS84；高德底图和热点返回 GCJ-02，只转换一次。旧采集器导出的种子数组已做过转换，不能再次转换。自取坐标不能冒充已核验的 POI 绑定；没有原生 POI 的地点仍可走目录入口。扩充中不改变发言时的实时位置校验，也不把浏览地图的位置用于发言认证。

## 待扩充数据格式

复制同目录 `map-expansion-batch.example.json` 作为独立批次，填入 `places`；不要覆盖现有种子。下面仅为字段模板，`null` 坐标故意不能通过校验，不能当真实地点导入：

```json
{
  "name": "完整且可区分的名称",
  "type": "教学楼",
  "description": "用途、入口等必要信息",
  "latitude": null,
  "longitude": null,
  "map_pois": []
}
```

核验过的关联格式为 `{"provider":"amap","poi_id":"真实POI编号","name":"原生地图名称"}`，不得编造编号。区域、简称、来源与核验记录暂放批次的维护记录；当前数据库尚无独立校区/别名字段。若决定跨校区扩充，先设计稳定校区 ID、区域和别名迁移，再导入，不依赖显示名称前缀区分身份。

## 只读预检

在 `backend` 目录运行（Windows 用 `.venv\Scripts\python.exe`，平板用 `.venv/bin/python`）：

```powershell
.venv\Scripts\python.exe tools/audit_map_catalog.py
.venv\Scripts\python.exe tools/audit_map_catalog.py --candidates ../docs/map-expansion-batch.example.json
```

旧采集器数组加 `--candidate-crs WGS84` 明确声明。`--catalog <文件路径>` 可使用最新建筑接口导出的 JSON 数组作为比对基线；默认只是仓库种子，无法发现生产库后续的管理员绑定变动。

工具检查空名称、超长字段、无效或颠倒的经纬度、重名、重复/抢占 POI，以及 25 米内需人工确认的近邻。输出分类数量、已绑定数量、错误和警告；只读文件，不联网、不连接数据库、不写入或删除数据。声明 WGS84 不代表坐标真实可靠，原生地图位置、楼栋入口和校区仍需实地或地图核验。

## 后续正式扩充流程

1. 确认范围与首批清单；保留原始采集文件，人工核验重名、相邻楼和 POI。
2. 导出最新建筑及绑定快照，预检后明确列出“新增 / 修改已有 ID / 待确认”。新增与修正不能混为一次按名称覆盖。
3. 实现独立、事务性的增量导入；支持 dry-run、稳定来源键/批次回执、防重复和回滚记录。现有演示 `seed` 会改写匹配名称的字段，不能用来做生产扩充。
4. 备份生产数据库，在副本演练并检查历史课表、建筑 ID、聊天室消息和已有管理员绑定均未改变，再同步平板。
5. 手机/网页验收原生点选、目录搜索、没有 POI 的地点入口、同名建筑和大目录性能。

本次只完成自动定位、目录容量修正和扩充预检准备；没有新增真实地点、批量采集外部数据、迁移数据库或发布生产后端。

前端 520 项单元测试、后端目录预检/地点/绑定 25 项测试，以及地图桌面/手机尺寸 6 项端到端测试通过，网页生产构建通过。地图测试涵盖无需按钮定位、原生选楼与频道返回、定位权限拒绝、SDK 不可用和 145 个地点的完整目录。浏览器测试使用 GPS 和地图 SDK 事件替身，原生权限逻辑使用插件替身；尚未完成此次 Android 真机授权/GPS 验收，也未同步安装手机。

## 实现依据

- [Capacitor 定位权限与位置 API](https://capacitorjs.com/docs/apis/geolocation)：系统授权仍需用户同意，地图只在前台取位置。
- [高德坐标转换说明](https://lbs.amap.com/api/javascript-api-v2/guide/transform/convertfrom)：区分设备坐标与底图坐标，避免重复转换。
