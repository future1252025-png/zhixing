# 05_系统架构设计：系统架构设计

## 1. 总体架构

系统采用前后端分离架构。

```text
用户浏览器
   ↓
Vue 3 前端
   ↓ HTTP / WebSocket
FastAPI 后端
   ↓
SQLite / MySQL 数据库
```

## 2. 技术架构

| 层级 | 技术 |
|---|---|
| 前端框架 | Vue 3 + Vite |
| 后端框架 | FastAPI |
| 数据库 | SQLite，后续 MySQL |
| ORM | SQLAlchemy |
| 数据校验 | Pydantic |
| 登录认证 | JWT |
| 实时通信 | WebSocket |
| 地图方式 | 卡通地图 + 建筑点位 |
| 定位 | 浏览器 Geolocation API |
| 部署 | Nginx + Uvicorn / Docker 可选 |

## 3. 后端分层

```text
backend/
├── main.py                 # FastAPI 入口
├── database.py             # 数据库连接
├── models/                 # SQLAlchemy 模型
├── schemas/                # Pydantic 请求和响应模型
├── routers/                # API 路由
├── services/               # 业务逻辑
├── utils/                  # 工具函数
└── core/                   # 配置、鉴权、安全
```

## 4. 前端分层

```text
frontend/
├── src/
│   ├── api/                # 请求封装
│   ├── assets/             # 图片、地图底图
│   ├── components/         # 公共组件
│   ├── views/              # 页面
│   ├── router/             # 路由
│   ├── store/              # 状态管理，可选
│   └── utils/              # 工具函数
└── public/
```

## 6. 数据流说明

### 6.1 登录数据流

```text
用户输入账号密码
→ 前端调用 /api/auth/login
→ 后端验证账号密码
→ 返回 JWT token
→ 前端保存 token
→ 后续请求携带 token
```

### 6.2 地图数据流

```text
前端进入地图页
→ 请求 /api/buildings
→ 后端返回建筑列表和 map_x/map_y
→ 前端在卡通地图上渲染建筑点
```

### 6.3 聊天数据流

```text
用户进入建筑聊天室
→ 前端请求历史消息
→ 建立 WebSocket 连接
→ 用户发送消息前先定位
→ 后端判断位置是否合法
→ 合法则保存消息并广播
```

### 6.4 日程规划数据流

```text
用户打开日程页
→ 前端获取当前位置
→ 请求 /api/schedule/next
→ 后端读取下一节课
→ 计算距离和时间
→ 返回建议出发时间
```

## 7. 权限设计

| 角色 | 权限 |
|---|---|
| 未登录用户 | 只能访问登录页 |
| 学生用户 | 地图、聊天查看、定位发言、课程表、日程建议 |
| 管理员 | 学生功能 + 建筑管理 + 消息管理 + 举报处理 |

## 8. 安全设计

1. 密码使用哈希保存。
2. 使用 JWT 做接口鉴权。
3. 管理员接口需要校验 role。
4. 聊天发言需要位置校验。
5. 前台匿名，后台保存 user_id。
6. 消息支持举报和隐藏。
7. 对发言频率进行限制，防止刷屏。
