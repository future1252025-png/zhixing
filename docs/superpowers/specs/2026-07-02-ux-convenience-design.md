# 智行 CampusMind 用户便利体验设计规格

日期：2026-07-02

## 目标

在不新增大体量业务模块的前提下，补齐“用户能顺着走”的体验层。当前系统已经具备认证、地图、建筑留言、课表导入、课程表、出发建议和路线可视化，但很多入口、空状态、错误恢复和默认值仍需要用户自己摸索。本阶段目标是让用户从首次登录到完成一次出发建议的路径更短、更清楚、更少中断。

## 范围

本设计只覆盖前端用户便利改造和少量必要的前端状态管理，不改变核心后端业务规则，不引入真实 AI、真实教务统一认证、WebSocket、推送通知或新的地图 SDK 能力。

允许调整的范围：

- 登录后/首次打开的引导体验
- 首页快捷入口与下一步提示
- 课表空状态、导入入口、周次记忆和新增课程默认值
- 课表导入预览与未匹配建筑的处理提示
- 出发建议页的起点/终点选择、最近使用地点和错误兜底
- 建筑留言页定位提示和发送前确认
- 全局错误提示、加载态、空状态、可恢复操作

不做的内容：

- 不重写后端核心逻辑
- 不新增管理员后台
- 不实现真实 AI 识别课表
- 不实现真实地图路线规划之外的新导航能力
- 不实现 WebSocket 实时聊天
- 不接入真实湖北大学统一身份认证

## 推荐方案

采用“轻引导 + 智能默认值 + 页面内恢复”的方案。

相比做完整新手教程，这种方式更适合课程设计 MVP：开发成本低，不打断用户；相比只加按钮，它能把用户从“我不知道下一步点哪”带到“我现在能完成任务”。

## 核心用户路径

目标主流程：

1. 用户注册或登录。
2. 首次进入时看到简短启动/欢迎动画。
3. 首页提示下一步：导入课表或查看地图。
4. 用户导入 HTML/Excel 课表，系统自动预览并尽量匹配建筑。
5. 用户进入课表页，看到当前周完整课表。
6. 用户进入出发建议页，系统默认使用上次起点或推荐起点。
7. 用户搜索起点/终点或使用课程目标地点，生成建议路线。
8. 用户在建筑页查看留言，发送前可以快速使用当前建筑位置。

## 页面级设计

### 登录与首次打开

- 首次打开 App 时播放一次短启动动画，说明“课表、地图、留言、出发建议已接通”。
- 登录成功后播放课程路线票据动画。
- 如果能读取到下一节课，动画显示课程名、时间、教学楼和教室。
- 如果读取课程失败或没有课程，动画显示通用欢迎文案，不阻塞登录。

### 首页

- 首页保留下一节课票据和地图。
- 当没有课程时，优先显示“导入课表”和“手动新增课程”。
- 地图区域提供搜索框，用户不需要从长列表找建筑。
- 首页快捷入口只保留高频动作：导入课表、出发建议、本周课表。

### 课表页

- 课表按周次展示，并记住用户上次选择的周次。
- 课表用完整七列表格展示，避免横向拖动才能看全。
- 空白格可点击新增课程，并自动带入星期与时间段。
- 课程卡片点击后打开操作菜单，包含编辑和删除；不在卡片右上角显示删除叉。
- 删除前必须二次确认。

### 课表导入页

- 文件选择后先预览，不直接写入。
- 已匹配建筑的课程直接显示匹配结果。
- 未匹配建筑的课程集中提示“需要确认”，并把选择建筑的操作放在卡片内。
- 如果没有识别到课程，提示用户应上传课表页面导出的 HTML 或 Excel，而不是教务首页源码。

### 出发建议页

- 起点和终点都使用搜索选择，不让用户翻长列表。
- 起点优先使用最近选择的位置；没有最近位置时可默认选第一个校园地点，但要明确显示。
- 终点不选时使用下一节课地点。
- 允许用户手动指定终点，用于“我要去某个地点”的普通路线查询。
- 生成建议后展示下一节课、起点、终点、距离、步行时间、缓冲时间和建议出发时间。
- 如果高德路线失败，保留直线兜底，但提示只出现一次，不反复刷新干扰缩放。

### 建筑留言页

- 发送留言前明确提示“需要定位或使用当前建筑位置”。
- 浏览器定位失败时，保留“使用当前建筑位置”的快速兜底。
- 发送成功后自动滚动到底部。
- 留言统一匿名展示，保留距离建筑的提示。

## 状态与数据

建议新增或复用以下前端状态：

- `campusmind-launch-intro-seen-v1`：记录首次打开动画是否播放过。
- `campusmind-login-intro-pending`：登录后动画待播放标记。
- `campusmind-login-intro-snapshot`：登录动画课程快照。
- `campusmind-selected-week`：当前课表周次。
- 最近起点位置：可以放在 Pinia location store，并可后续持久化到 localStorage。

## 错误与恢复

所有关键错误提示都要给恢复动作：

- 登录失败：提示账号或密码错误，并保留输入。
- 地图失败：提示检查网络/Key，同时保留搜索结果或页面其它操作。
- 课表导入失败：提示文件类型和正确导出位置。
- 出发建议失败：提示是否没有课程、没有起点或没有可识别目的地。
- 留言定位失败：提供“使用当前建筑位置”兜底。

## 测试要求

前端测试应覆盖：

- 首次打开动画只播放一次。
- 登录动画能保存并消费下一节课快照。
- 课程周次读取与保存。
- 课表空格新增默认参数。
- 课程导入预览的已匹配/待确认计数。
- 地点搜索过滤。
- 出发建议起点/终点搜索。

验收命令：

- `cd frontend && npm test`
- `cd frontend && npm run build`
- `cd backend && python -m pytest`

## 验收标准

- 新用户不看说明也能完成：注册/登录、导入课表、查看课表、生成一次出发建议。
- 没有课程、没有地点、没有定位权限、地图失败时都有下一步操作。
- 主要页面没有必须横向拖动才能理解核心内容的情况。
- 导入、定位、路线生成、留言发送都有明确反馈。
- 不引入超出 MVP 的真实 AI、WebSocket、真实统一认证等后置功能。
