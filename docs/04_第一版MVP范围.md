# 04_第一版MVP范围：第一版 MVP 范围

## 1. MVP 目标

在 4 周内完成一个可以本地运行、可以小范围部署测试的校园服务系统。

MVP 不追求功能完整，而是要验证核心闭环：

```text
登录 → 查看校园地图 → 点击建筑 → 进入聊天室 → 定位判断 → 发送消息 → 添加课程 → 生成出发建议
```

## 2. 第一版必须完成

| 模块 | 功能 | 优先级 |
|---|---|---|
| 用户认证 | 注册、登录、JWT | P0 |
| 地图 | 卡通地图展示、建筑点位 | P0 |
| 建筑 | 建筑列表、详情 | P0 |
| 聊天 | 建筑聊天室、消息列表、发消息 | P0 |
| 定位 | 判断是否在建筑附近 | P0 |
| 课程 | 添加、查看、修改、删除课程 | P0 |
| 日程 | 下一节课识别、出发时间建议 | P0 |
| 管理 | 建筑管理、消息管理 | P1 |
| 举报 | 用户举报、管理员处理 | P1 |
| 提醒 | 前端提醒 | P1 |

## 2.1 项目初期建议的最小闭环

由于当前项目尚未开始，建议第一阶段先实现更小的可运行闭环：

```text
注册登录
建筑列表与详情
地图点位展示
单建筑聊天室
HTTP 获取消息和发送消息
发送消息时进行定位校验
课程表增删改查
下一节课出发建议
```

第一阶段可以暂缓 WebSocket、多频道、完整管理员后台、举报工作流和系统提醒。等主流程跑通后，再逐步增强。

## 3. 第一版暂不完成

| 功能 | 暂不做原因 |
|---|---|
| 真实校园统一身份认证 | 学校系统接入门槛高 |
| 真实室内定位 | GPS 室内精度不足 |
| 精确到楼层导航 | 数据采集成本高 |
| AI 大模型深度规划 | 开发时间不足 |
| 自动导入教务课表 | 需要教务系统接口 |
| 原生手机 App | 开发量大 |
| 全校全部建筑 | 数据量较大，先做主要建筑 |
| 支付、校园卡等功能 | 不属于核心功能 |

## 4. MVP 验证标准

完成后，用户应该可以做到：

1. 登录系统。
2. 在地图上看到湖北大学主要建筑。
3. 点击某个建筑。
4. 查看该建筑信息。
5. 进入该建筑聊天室。
6. 在建筑范围内发送匿名消息。
7. 不在范围内时被禁止发送。
8. 添加自己的课程。
9. 查看下一节课出发建议。
10. 接收到简单提醒。
