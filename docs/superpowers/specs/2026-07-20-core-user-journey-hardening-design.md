# 智行核心用户链路加固设计

## 1. 背景

本阶段覆盖“登录 → 课表 → 课程地点 → 首页摘要 → 出发建议”这条核心用户链路。目标不是继续做表面视觉优化，而是消除会让用户看到错误课程、丢失地点、导入半份课表、登录后卡死或读取到其他账号状态的底层问题。

当前基线验证结果为：

- 前端 Vitest：94 项通过。
- 后端 pytest：65 项通过，存在 1 条第三方弃用警告。
- 前端生产构建通过。

这些测试说明现有已覆盖行为能够运行，但不能证明核心业务规则正确。当前测试主要集中在工具函数和接口单元行为，缺少完整用户流程、导入事务、跨账号隔离及视觉可读性验证。

## 2. 已确认的产品决策

1. 第一阶段优先核心用户链路，地图和社区留到后续独立阶段。
2. 教学周自动计算。
3. 用户在课表页设置和修改学期开始日期。
4. 手动切换周次仅用于浏览，首页和出发建议始终使用真实当前周。
5. 同一天、时间重叠且周次有交集的课程禁止保存。
6. 建筑和教室都是课程必填信息。
7. 导入文件是导入课程的事实来源，课程名称、星期、节次或时间、教师、周次、地点和教室不得被静默省略、合并或改写。
8. 导入存在任意无法识别、地点不完整或课程冲突时，整批禁止提交。
9. 任何卡片、按钮、选中态、加载态或动画都不能降低文字可读性或用高亮层遮挡文字。

## 3. 目标与非目标

### 3.1 目标

- 让首页、课表和出发建议共享同一套教学周与课程规则。
- 让后端成为课程完整性、周次和冲突判断的最终权威。
- 让课表导入无损、可追溯、可定位错误并具备事务原子性。
- 让登录过期和账号切换具有一致、可恢复且不串数据的行为。
- 让课程地点在课表卡片、首页摘要和出发建议中保持显著、完整且一致。
- 建立移动端用户流程与文字可读性的发布阻断门槛。

### 3.2 非目标

- 本阶段不重写地图渲染、建筑社区或留言系统。
- 本阶段不实现多学期历史归档，只维护每个用户的当前学期设置。
- 本阶段不改变建筑基础数据的来源与坐标体系。
- 本阶段不以重构全部前端页面为目标，只拆分本次改动涉及的超大课程页面。

## 4. 当前问题与根因

### 4.1 教学周没有统一事实来源

前端使用本地存储中的手动周次，后端出发建议直接按星期和时间查找课程，并完全忽略课程周次。结果是首页、课表和出发建议可能对“当前课程”得出不同结论。

### 4.2 课程冲突只被动暴露

后端目前只校验单门课程时间格式，不检查已有课程或同批导入课程。出发建议遇到同一时间多门课程时只能选择其中一门并给出警告，错误数据已经进入数据库。

### 4.3 导入会丢失信息并产生部分写入

当前导入实现存在以下问题：

- 不符合解析正则的课程块会被静默跳过。
- 缺失地点时会自动写入“待确认教室”占位。
- 原始地点整体进入 `room_name`，建筑与教室没有可靠拆分。
- 前端逐门调用新增课程接口，中途失败会留下部分课程。
- 页面宣称支持 `.xls`，后端实际只解析 HTML 与 `.xlsx`。

### 4.4 登录与本地状态没有形成统一会话边界

请求层没有统一处理 401。令牌过期后，不同页面各自显示错误或停留在不可用状态。已选周次、最近操作等本地缓存也没有按用户隔离，账号切换可能读取到上一个账号的界面状态。

### 4.5 可读性依赖局部样式约定

当前没有自动化对比度与状态截图门槛。背景、选中高亮或动画层变化后，文字可能继承到错误颜色；仅靠人工查看静态页面无法覆盖按下、选中、禁用、加载和错误状态。

## 5. 总体架构

核心链路采用“前端解释、后端裁决、数据库原子提交”的纵向闭环：

1. Vue 页面负责采集输入、展示状态和提供恢复路径。
2. 类型化 API 层统一请求、响应和错误结构。
3. 后端领域服务统一处理学期、周次、冲突、地点完整性和导入规则。
4. SQLAlchemy 会话在单个事务中完成写入，任何错误都会回滚。
5. 首页和出发建议只消费后端已经验证的课程事实，不复制规则。

领域职责拆分为：

- `SemesterService`：当前学期设置、真实教学周及学期前后状态。
- `WeekRule`：周次表达式解析、单双周、集合展开和交集判断。
- `CoursePolicy`：课程时间范围、地点完整性、重复和冲突判断。
- `ImportService`：文件无损解析、逐行错误、建筑映射、全量校验和原子提交。

## 6. 数据模型

### 6.1 `semester_settings`

每个用户最多一条当前学期设置：

- `id`
- `user_id`，唯一外键
- `start_date`，第一周星期一
- `total_weeks`，默认 20
- `created_at`
- `updated_at`

当前周计算公式为：

```text
floor((当前本地日期 - start_date) / 7) + 1
```

应用时区固定为 `Asia/Shanghai`。返回状态分为：

- `unconfigured`：尚未设置。
- `before_term`：早于开始日期。
- `active`：位于第 1 至 `total_weeks` 周。
- `after_term`：超过学期总周数。

未配置时，首页和出发建议不得猜测周次；它们显示说明及“前往课表设置”入口。

### 6.2 `courses`

保留现有课程字段，并强化以下约束：

- `course_name` 必填。
- `weekday` 为 1 至 7。
- `start_time < end_time`。
- `building_id` 必须指向有效建筑。
- `room_name` 去除首尾空白后仍必须非空。
- `weeks` 保存规范化的可执行周次表达式。
- `source_kind` 为 `manual` 或 `import`。

数据库层保留外键，领域层负责冲突规则。课程删除时，对应导入来源记录级联删除。

### 6.3 `course_import_sources`

导入课程拥有一条一对一来源记录，用于保证可追溯与无损：

- `course_id`，唯一外键。
- `filename`
- `file_sha256`
- `source_row`
- `raw_course_name`
- `raw_weekday`
- `raw_time_or_section`
- `raw_teacher`
- `raw_weeks`
- `raw_location`

课程执行字段用于筛选、冲突和导航；来源字段用于展示文件原文和排查解析问题。建筑映射不得覆盖 `raw_location`。

### 6.4 版本化迁移

新增表和字段使用版本化数据库迁移。现有启动时 `ALTER TABLE` 兼容逻辑只在迁移过渡期保留，迁移完成后移除，避免生产数据库结构依赖应用启动顺序。

## 7. 周次与冲突规则

### 7.1 周次表达式

后端是周次解析的唯一权威，至少支持：

- `1-16`
- `1,3,5,7`
- `1-16(单)`
- `1-16(双)`
- 上述形式的中文标点和常见空白变体

解析结果为显式周次集合。无法解析的表达式不能保存或导入，错误必须指向具体字段与源行。

### 7.2 时间重叠

时间区间按半开区间处理：

```text
existing.start < candidate.end
and candidate.start < existing.end
```

一门课结束时间等于另一门课开始时间时不视为冲突。

### 7.3 冲突条件

只有同时满足以下条件才冲突：

1. 属于同一用户。
2. 星期相同。
3. 时间区间重叠。
4. 周次集合存在交集。

编辑课程时排除自身。批量导入需要同时检查：

- 导入课程与数据库已有课程。
- 同一导入文件内部课程。

出现冲突时返回冲突课程、星期、时间和重叠周次，并保持用户当前表单或导入预览。

## 8. 无损课表导入

### 8.1 支持格式

页面和后端能力保持一致，支持：

- HTML / HTM
- XLS
- XLSX

每种格式都必须拥有固定样例和解析契约测试。

### 8.2 预览阶段

预览响应为文件中每个课程候选生成稳定的 `row_ref`，包含：

- 文件行号或表格坐标。
- 全部原始字段。
- 解析后的执行字段。
- 建筑匹配结果与置信状态。
- 字段级错误列表。

非空但无法解析的课程候选必须作为错误项返回，不能从结果中消失。表头、空单元格和明确非课程区域可以忽略。

源文件字段在预览中只读。用户只能处理“执行映射”，例如确认原始地点对应的建筑，或在解析无法拆分但原文包含教室时确认教室映射；原始字段始终保留。

### 8.3 提交阶段

前端提交：

- 原始文件。
- 预览阶段确认的 `row_ref → building_id / room mapping`。

后端重新读取原始文件并完成：

1. 重新计算 SHA-256。
2. 重新解析全部课程候选。
3. 验证每个 `row_ref` 和映射。
4. 验证地点、周次、时间和冲突。
5. 在同一事务中写入课程及来源记录。

任意一步失败都整体回滚。接口不得循环调用单门课程创建逻辑并逐次提交。

### 8.4 明确禁止

- 静默跳过无法识别的课程。
- 自动写入“待确认教室”等占位数据。
- 把建筑与教室合并为不可解析的单一执行字段。
- 为匹配建筑而修改文件原文。
- 导入部分成功、部分失败。

## 9. API 契约

### 9.1 学期

```text
GET /api/semester
PUT /api/semester
```

`GET` 返回配置状态、开始日期、总周数、真实当前周和学期状态。`PUT` 只允许当前用户修改自己的设置。

### 9.2 课程

保留现有课程 CRUD 路径。创建和更新在后端执行完整地点与冲突校验。冲突使用 HTTP 409；普通字段验证使用 HTTP 422；不存在的建筑或课程使用 HTTP 404。

### 9.3 导入

```text
POST /api/courses/import/preview
POST /api/courses/import
```

预览不写数据库。提交接口接收原文件和映射并执行原子导入。

### 9.4 出发建议

出发建议不再从前端接收“当前周”。后端根据当前用户的学期设置和服务器当前日期确定真实周次，只查找该周实际生效的课程。未配置学期时返回结构化 `semester_unconfigured` 错误。

### 9.5 统一错误结构

业务错误统一为：

```json
{
  "code": "course_conflict",
  "message": "与《高等数学》上课时间冲突",
  "fields": ["weekday", "start_time", "weeks"],
  "details": {
    "overlap_weeks": [7, 8, 9]
  }
}
```

前端按 `code` 选择恢复动作，不再依赖英文字符串匹配。

## 10. 前端用户旅程

### 10.1 登录与会话

- 请求层统一处理 401。
- 首次 401 清理令牌、当前用户及该用户的内存状态。
- 多个并发 401 只触发一次提示与跳转。
- 登录页保留原目标地址，重新登录后返回原页面。
- 提示文案明确为“登录已过期，请重新登录”。

### 10.2 账号隔离

选择的浏览周次、最近操作和其他用户相关缓存使用包含用户 ID 的键：

```text
campusmind:{user_id}:{key}
```

未加载当前用户前不读取用户级缓存。退出登录清理当前会话状态，下一账号不得继承上一账号的浏览周次和最近记录。

### 10.3 课表页

- 未设置学期时，在课表页顶部显示轻量设置卡片。
- 用户确认开始日期后立即显示真实当前周。
- 用户可以浏览其他周；页面始终区分“当前周”和“正在查看第 N 周”。
- 修改学期日期后，首页摘要和出发建议重新获取真实周次。
- 课程卡片把“建筑 + 教室”作为一级信息，不在次要描述中省略。

### 10.4 导入页

- 显示文件名、源行号和全部原始字段。
- 原始字段只读，执行映射单独展示。
- 字段错误精确关联到课程项与输入控件。
- 有未确认地点、教室、周次或冲突时，提交按钮禁用且文字清楚说明原因。
- 导入失败保留文件、预览和映射，用户修正后直接重试。

### 10.5 首页与出发页

- 首页只显示真实当前周的当天课程。
- 下一节课必须展示建筑和教室。
- 未配置学期、没有课程、课程已结束和定位失败使用不同空状态。
- 出发建议只在课程地点完整时生成。
- 建议卡片同时展示上课时间、建议出发时间、起点、建筑和教室。

## 11. 前端可读性规则

### 11.1 颜色

- 正常正文文字与背景对比度不低于 4.5:1。
- 大字号文字和必要图形不低于 3:1。
- 次要文字不得只依靠低透明度表达层级。
- 每种语义表面显式绑定文字色，不依赖跨组件继承。
- 禁用按钮仍需清楚表达按钮文字和禁用原因。

### 11.2 状态与动画

- 选中态使用背景、边框和图标共同表达，不能用高亮遮罩覆盖文字。
- 动画层不得位于交互文字上方。
- 加载状态保留操作语义，避免只显示无文字动画。
- `prefers-reduced-motion` 下保留完整信息和交互反馈。

### 11.3 视觉验收

以下状态都必须在移动端视口中检查：

- 默认
- 按下
- 选中
- 禁用
- 加载
- 成功
- 错误
- 系统深色偏好与强制颜色环境

## 12. 前端代码边界

本阶段只拆分被修改的超大课程页面：

- 学期设置状态进入独立 store。
- 课程列表、课程卡片和学期设置卡片成为独立组件。
- 导入文件状态、预览映射和提交逻辑进入专用 composable。
- 导入预览项成为独立组件。
- API 错误解析集中到单一模块。

首页和出发页只通过 store 与 API 获取数据，不复制周次解析和冲突逻辑。

## 13. 测试策略

### 13.1 后端

- 学期开始前、第一周、学期中、最后一周和学期结束后的当前周计算。
- 周次范围、离散周次、单双周和非法表达式。
- 时间相邻不冲突、时间重叠但周次不交集、时间与周次均重叠。
- 创建、编辑和批量导入冲突。
- 出发建议忽略非当前周课程。
- 导入原始字段完整保存。
- 无法解析项不会静默消失。
- 同批冲突、已有课程冲突和数据库异常时零写入。
- 学期与课程均严格按当前用户隔离。

### 13.2 前端

- 学期未设置与已设置状态。
- 当前周和浏览周次的区分。
- 课程地点完整展示。
- 导入源字段只读、映射可确认、错误可定位。
- 禁用与加载按钮文字清楚可见。
- 401 只触发一次退出并保留目标地址。
- 用户级缓存键按用户隔离。

### 13.3 端到端

以 390×844 移动视口完整走通：

1. 登录。
2. 在课表页设置学期日期。
3. 手动创建完整课程。
4. 阻止冲突课程。
5. 导入包含建筑和教室的课表。
6. 验证首页当天课程。
7. 验证出发建议使用真实当前周和完整地点。
8. 模拟令牌过期并重新登录返回原页面。

端到端流程同时采集关键状态截图并执行文字对比度检查。

## 14. 迁移与兼容

1. 先新增版本化迁移、学期设置表和导入来源表。
2. 现有课程继续可读，`source_kind` 迁移为 `manual`。
3. 现有课程若教室为空或只有占位文字，标记为需要修正；在修正前不参与出发建议。
4. 前端先兼容学期未配置状态，再启用后端真实周次。
5. 导入提交接口上线后移除前端逐门创建循环。
6. 旧的用户无关本地缓存不迁移为其他账号数据；首次加载后使用用户级键重新建立。

## 15. 验收标准

满足以下全部条件才视为第一阶段完成：

- 首页、课表和出发建议对真实当前周的判断一致。
- 未设置学期时不展示猜测课程或猜测出发建议。
- 冲突课程无法通过前端或直接 API 写入。
- 所有已保存课程均有有效建筑与非空教室。
- 导入文件中的课程候选全部出现在预览或明确错误列表中。
- 导入原始地点和教室可追溯，系统不会擅自省略或改写。
- 任意导入失败不会写入任何课程。
- 令牌过期后可恢复登录并返回原页面。
- 两个账号之间不共享用户级本地状态。
- 关键移动端状态不存在文字被高亮、动画、遮罩或低对比度背景影响的问题。
- 前端单元测试、后端测试、生产构建和移动端端到端流程全部通过。

## 16. 后续阶段
